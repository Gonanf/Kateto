## 2. FastAPI HTTP Server (`kateto/plugins/system/http_server.py`)

**New file.** Mirrors MCP server surface for dashboard consumption.

**Endpoints:**
| Method | Path | Description |
|--------|------|-------------|
| GET | `/events` | List registered events + contracts (Pydantic → JSON schema) |
| GET | `/events/stream` | WebSocket: live event stream from bus |
| GET | `/voices` | List voices with status (enabled, speaking_state) |
| POST | `/events/send` | Send event manually (equiv to MCP send_event) |
| POST | `/plugins/{name}/enable` | Enable plugin |
| POST | `/plugins/{name}/disable` | Disable plugin |
| GET | `/plugins` | List all plugins with status |

**Architecture:**
- FastAPI app with lifespan (start/stop)
- WebSocket endpoint hooks into PluginManager as event observer
- Event contracts auto-scanned from `manager.get_event_registrations()`
- No voice authorization needed (dashboard is system-level, not per-voice)
- Shares event discovery logic with MCP server (both read from manager)

**Dependencies:** `fastapi` + `uvicorn` (already transitive via gradio/mcp, add as direct deps)

**Wire into runtime:** `run_mode.py` starts HTTP server in `RuntimeOwner.start()` alongside MCP servers.

## 6. §4b pydantic-ai in Voices

**Goal:** Replace `OpenAIAgentProvider` manual tool-calling loop with pydantic-ai `Agent`.

**Files:** `kateto/voices/base.py`, `kateto/voices/factory.py`, `kateto/providers/agent.py`, `pyproject.toml`

**Approach:**
1. Add `pydantic-ai` as direct dependency in `pyproject.toml`
2. In `VoiceAgent`, when agent provider is configured, create a `pydantic-ai.Agent` instead of using `OpenAIAgentProvider`
3. The Agent gets: system prompt, tools (from VoiceToolExecutor), model config
4. Replace `_agent_loop()` with `agent.run()` / `agent.run_stream()` — pydantic-ai handles the tool-calling loop internally
5. Keep `OpenAICompatibleProvider` for non-agent path (plain generation without tools)
6. `VoiceToolExecutor` adapts to pydantic-ai's tool interface via `@agent.tool` decorator or `Tool` protocol

**Key constraint:** Structured output ONLY for `ShouldInterrupt` (§4b SPEC clarification). Voice generation stays free-form. pydantic-ai supports both modes.

**Migration path:**
- `factory.py`: Create `Agent(model, tools=..., system_prompt=...)` per voice
- `base.py._agent_loop()`: Replace manual loop with `agent.run_stream()` yielding tokens
- `base.py._handle_tool_calls()`: pydantic-ai handles this internally
- `providers/agent.py`: Keep `OpenAIAgentProvider` as fallback for non-agent path
